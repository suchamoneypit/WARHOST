## Map previews

The WebUI scenic and tactical slots show Overview and Preview from `webui/previews/` when `index.json` names them for that map. One pair comes from each battlefield's `Maps/*_Details.dat` (`edat` archive) and is shared by every scenario ID with that stem. On 2026-10-12 those bytes in the local install were WebP or PNG: `_2x2_Hesse_Details.dat` under `Data/PC/197351/201602/Maps/` holds `Overview.webp` and `Preview.webp`, and the file header sits before each of those names. Red Dragon's `RDPort_JungleLaw_Details.dat` holds `Overview.` and `Preview.` with the header after the name, and both payloads are PNG. On 2026-11-06 Highway to Oslo (`3474588989`), Ramstein (`3705706772`), and Arsenal (`3415339374`) stored that tactical entry as `review.` rather than `Preview.`: PNG, 1024×1024 for the two 2×2 maps and 1024×1536 for Two Hills, in the same slot between Overview and Splat_map. Scenic views in those packs are 424×272 PNG, the same size as the base-game lobby texture. Helbe (`3762638679`) and West Fulda (`3363584349`) `Maps/*_Details.dat` files are `edat` version 2 and contain no PNG or WebP. Each has one zstd frame; decompressing it yields raw bytes with no PNG, WebP, Overview, or Preview name. Their `*_Assets.dat` directories name `Overview.tgv` and `Preview.tgv` only, and the zstd frames in those asset packs are raw texture blocks, not PNG or WebP. The `.tgv` copies in `*_Assets.dat` are not read. Eugen's map guide names Overview as the lobby texture and Preview as the top-down texture ([complete map modding guide](https://steamcommunity.com/sharedfiles/filedetails/?id=3352892580)). The published image does not include the pictures, so those slots stay labeled Scenic view and Tactical zones until the folder is present beside the page.

For published file `1`, DepotDownloader printed `Unable to locate manifest ID for published file 1` and exited `0`, so the wrapper requires `Config.ini` on disk and does not trust the exit status alone. In [ContentDownloader.cs](https://raw.githubusercontent.com/SteamRE/DepotDownloader/DepotDownloader_3.4.0/DepotDownloader/ContentDownloader.cs) at that tag, read 2026-10-10, `DownloadPubfileAsync` passes `hcontent_file` to the depot download as a manifest ID, and the manifest's files are filtered through `TestIsFileIncluded`, which applies the file list, before any chunk is queued. In [Program.cs](https://raw.githubusercontent.com/SteamRE/DepotDownloader/DepotDownloader_3.4.0/DepotDownloader/Program.cs) at that tag, `-filelist` turns the filter on with an empty list before reading the file, so a list that cannot be read downloads nothing.
