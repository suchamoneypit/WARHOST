## DepotDownloader measurements

Measured on 2026-10-10 with DepotDownloader 3.4.0 and no Steam account:

| Item | `file_size` | `Config.ini` transferred | Manifest saved | `Version` |
| --- | --- | --- | --- | --- |
| `3811913066` Red Dragon | 9,059,324,422 bytes | 416 bytes (551 uncompressed) | 419,989 bytes | 27 |
| `3474588989` Highway to Oslo | 148,918,317 bytes | 384 bytes (485 uncompressed) | 13,745 bytes | 14 |

The manifest IDs DepotDownloader requested, `3167211120192437934` and `7803733855267144859`, equal `hcontent_file` from the details call. For published file `1`, DepotDownloader printed `Unable to locate manifest ID for published file 1` and exited `0`, so the wrapper requires `Config.ini` on disk and does not trust the exit status alone. With networking removed it printed `Could not connect to Steam after 10 tries` and exited `1` after about 55 seconds. In [ContentDownloader.cs](https://raw.githubusercontent.com/SteamRE/DepotDownloader/DepotDownloader_3.4.0/DepotDownloader/ContentDownloader.cs) at that tag, read 2026-10-10, `DownloadPubfileAsync` passes `hcontent_file` to the depot download as a manifest ID, and the manifest's files are filtered through `TestIsFileIncluded`, which applies the file list, before any chunk is queued. In [Program.cs](https://raw.githubusercontent.com/SteamRE/DepotDownloader/DepotDownloader_3.4.0/DepotDownloader/Program.cs) at that tag, `-filelist` turns the filter on with an empty list before reading the file, so a list that cannot be read downloads nothing.

The Dockerfile downloads `DepotDownloader-linux-x64.zip` from release [DepotDownloader_3.4.0](https://github.com/SteamRE/DepotDownloader/releases/tag/DepotDownloader_3.4.0) (33,442,357 bytes, SHA-256 `a999dec66b4850fc961bd50366696d23c2d0fad7b18790e6a5647b2f19097a53`), checks the hash, and unpacks it with `python3 -m zipfile` into `/opt/depotdownloader`, with its GPL-2.0 `LICENSE`. `/usr/local/bin/DepotDownloader` links to the 78,977,777-byte self-contained binary. `DepotDownloader -V` printed `DepotDownloader v3.4.0+c553ef4d60c00a4f5fd16c9fe017f569001589ff` and `Runtime: .NET 9.0.0 on Debian GNU/Linux 13 (trixie)`. Eugen's image at digest `sha256:fb498aa82d7b15e3978bac51240e1243be3e19232ba0e66a6d947ec4b4364fe5` has six layers totaling 84,020,395 bytes compressed. It has `wget`, `sha256sum`, `python3`, `timeout`, and `flock`, has no `curl`, `unzip`, or ICU library, and its `/bin/sh` is `dash`. The wrapper sets `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1` because ICU is absent. The .NET runtime creates an empty `/tmp/.dotnet/shm` in the container regardless of `TMPDIR`.

On 2026-10-10 those layers were unpacked into a directory. The Dockerfile's `RUN` line, `tests/entrypoint_test.sh` under `dash`, and the wrapper with the real DepotDownloader and Steam ran inside it under `unshare` and `chroot`, with a stub in place of `entrypoint2.sh`. `3811913066-3474588989` became `3811913066/27-3474588989/14` in 7 seconds. The next start used the cache, and with networking removed the start after that wrote the saved numbers with two warnings. Nothing outside the settings folder changed except `/tmp/.dotnet/shm`. No `docker build` ran, and no container has run the rebuilt image.

`ModGenVersion = 201602 ; ModGen revision, do not modify` is the same line in all nine `Config.ini` files in the local Steam library on 2026-10-10, while `Version` differs per mod. The comment on `Version` says to increment it when an update is incompatible. `3811913066/15` joined while `Version` was 15, and `3811913066/0` was refused, so the ModList number is `Version`.

## Eugen settings reference

Eugen's Docker Hub text documents `login.ini`, `variables.ini`, `params_for_ai.json`, and `maps.ini` (map rotation only). It names the `variables.ini` keys but never defines a `Map` key; the base-game table column is "Map Base Id". The `eugensystems/warno:latest` image read on 2026-10-09 is about 80 MB compressed: Debian base, a 27 MB `warno-server`, default `settings/variables.ini` and `settings/params_for_ai.json`, and no game data layer. What the server fetches at first start was not observed.

`ModList` on that same Docker Hub page tells joining clients to download and enable a missing workshop mod. `entrypoint2.sh` in image digest `sha256:fb498aa82d7b15e3978bac51240e1243be3e19232ba0e66a6d947ec4b4364fe5` does not download files. It runs `warno-server -listenport=$EXPOSEDPORT -ip=$EXPOSEDIP -port=$EXPOSEDPORT -ipmms 178.32.126.73 -portmms 10002`.

Eugen's `variables.ini` reference gives `GameType` `0` as NATO vs PACT. A later sentence on the same page calls that mode Allies vs Axis. The enumerated table is the one this wrapper follows (`GameType = 0`). `NbMaxPlayer` maximum is 20, which the wrapper also enforces. `MaxTeamSize` is only "Maximum number of players in each team." That page never says either value must match the size token in the scenario ID. Separate Map Base Ids exist for sizes such as `_2vs2_` and `_4vs4_`. Source: [Configuration file `variables.ini`](https://hub.docker.com/r/eugensystems/warno), registry `full_description` fetched 2026-10-09 (`last_updated` 2026-09-17) from <https://hub.docker.com/v2/repositories/eugensystems/warno/>.

The same page documents `CoopVsAI`: `0` off, `1` humans on the first team, `2` humans on the second. `AutoFillAI` fills empty slots and cannot be combined with `CoopVsAI`; this page does not write it. `params_for_ai.json` holds deck name, deck code, and `iaLevel` 1 through 6 for sides `0` and `1`. The AI picks one deck from that side at random. `MaxTeamSize` is one cap for each team. A PvE setup of 2 humans and 2 AI writes `CoopVsAI` `1` or `2`, `NbMaxPlayer` 4, `NbMinPlayer` 2, `MaxTeamSize` 2, and `DeltaMaxTeamSize` 0. A count of 2 humans and 4 AI writes `NbMaxPlayer` 6, `NbMinPlayer` 2, `MaxTeamSize` 4, and `DeltaMaxTeamSize` 2. That uses the only documented keys that allow a size difference. The human side is not given a smaller cap of its own. Whether the server spawns the extra AI has not been tried. The Hesse seed does not set `CoopVsAI`. A PvP save adds that key only when a PvE setup save already wrote it, and then sets it to `0` and `DeltaMaxTeamSize` to `0`. Operations and Army General are not in that Docker Hub page. The `SM_*` names stay unused as a lobby `Map`.
